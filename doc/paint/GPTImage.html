绘图模型

GPT-Image-2 绘图教程

gpt-image-2 使用 OpenAI Images API 风格调用。按照 D:\video\Huanxing-ImageHub 的实际请求逻辑，文生图直接调用 POST /v1/images/generations；带参考图时优先调用 POST /v1/images/edits 并用 multipart/form-data 上传 image[]。

令牌要求

gpt-image-2 建议使用令牌分组为 gptimage 的 API 令牌。文档中的“试一试”会直接请求当前 API 域名，请填写可用的 sk-... 令牌。

可用接口

功能接口请求格式说明
文生图POST /v1/images/generationsJSON只传提示词和图片参数。
参考图 / 图片编辑POST /v1/images/editsmultipart/form-data上传一张或多张参考图，字段名使用 image[]。

模型与尺寸

参数推荐值说明
modelgpt-image-2当前文档默认模型。ImageHub 也兼容 gpt-image-2-pro、gpt-image-2-4k、gpt-5.4-image-2 等 image-2 系列模型，是否可用取决于你的渠道与令牌权限。
size1024x1024、1536x1024、1024x1536、2048x1152、3840x2160ImageHub 会按宽高比和分辨率计算最终 size。最长边不超过 3840，宽高建议为 16 的倍数。
qualityauto、low、medium、high草稿图可用 low，正式出图可用 high。部分 VIP/Pro 模型可能忽略或限制该字段。
output_formatpng、jpeg、webpImageHub 默认 png；只有非 png 时才显式传给上游。
response_formaturl 或 b64_json文档示例默认用 url，便于直接查看图片。ImageHub 代理内部使用 b64_json 再转成浏览器本地图片。
n1建议固定为 1；多图请多次请求或由客户端批量队列控制。

功能分类

文生图

只提供文本提示词生成图片。这个请求对应 ImageHub 无参考图时的最终上游调用：POST /v1/images/generations，请求体为 JSON。

示例：

curl https://api.huanxing.ai/v1/images/generations \
  -H "Authorization: Bearer sk-你的令牌" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "一只橘猫戴着橙色围巾抱着水獭，温暖插画风格",
    "size": "1024x1024",
    "quality": "high",
    "output_format": "png",
    "response_format": "url",
    "n": 1
  }'
POST /v1/images/generations
使用 url 可直接返回图片地址；b64_json 响应较长，页面会截断显示。

参考图 / 图片编辑

上传参考图进行图生图或图片编辑。这个请求对应 ImageHub 有参考图时的优先路径：POST /v1/images/edits，使用 multipart/form-data，参考图字段名为 image[]。

示例：

curl https://api.huanxing.ai/v1/images/edits \
  -H "Authorization: Bearer sk-你的令牌" \
  -F 'model="gpt-image-2"' \
  -F 'prompt="保留参考图主体，把背景改成暖色调产品海报，干净商业摄影风格"' \
  -F 'image[]=@"/path/to/reference.png"' \
  -F 'size="1024x1024"' \
  -F 'quality="high"' \
  -F 'output_format="png"' \
  -F 'response_format="url"' \
  -F 'n="1"'
POST /v1/images/edits
可选择多张参考图；字段名会按 ImageHub 请求方式作为 image[] 上传。

参考图 fallback：JSON image 数组

ImageHub 在 /v1/images/edits 不可用时，会退回 /v1/images/generations，并把参考图放入 JSON 字段 image。值可以是 data URI，也可以是公网可访问 URL。

示例：

curl https://api.huanxing.ai/v1/images/generations \
  -H "Authorization: Bearer sk-你的令牌" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "参考这张图的主体姿态，生成一张商业摄影产品图",
    "image": [
      "https://example.com/reference.png"
    ],
    "size": "1024x1024",
    "quality": "high",
    "output_format": "png",
    "response_format": "url",
    "n": 1
  }'
POST /v1/images/generations
请把示例 URL 换成公网可访问图片地址；本地文件请使用上方 multipart 编辑接口。

参数说明

参数类型适用接口说明
modelstring生成、编辑模型名称，默认 gpt-image-2。
promptstring生成、编辑图片描述或编辑要求。ImageHub 会把负面提示词追加到提示词末尾。
image[]file编辑multipart 上传参考图，支持多张。ImageHub 优先使用该方式。
imagearray<string>生成 fallbackJSON 参考图数组，元素为 data URI 或公网 URL。
sizestring生成、编辑输出尺寸。常用 1024x1024、1536x1024、1024x1536、2048x1152、3840x2160。
qualitystring生成、编辑auto、low、medium、high。
output_formatstring生成、编辑png、jpeg、webp。
response_formatstring生成、编辑url 返回图片地址；b64_json 返回 Base64 图片数据。
input_fidelitystring编辑可选 high，用于尽量保留参考图主体和细节。
ninteger生成、编辑建议固定为 1。

响应示例

当 response_format 为 url 时，响应通常包含图片 URL：

{
  "created": 1776923999,
  "data": [
    {
      "url": "https://.../file_download/xxxxxxxx.png",
      "revised_prompt": "..."
    }
  ]
}

当 response_format 为 b64_json 时，响应会包含 Base64 图片数据：

{
  "created": 1776923999,
  "data": [
    {
      "b64_json": "iVBORw0KGgoAAAANSUhEUgAA...",
      "revised_prompt": "..."
    }
  ]
}

不建议的调用方式

不要用 Chat Completions 或 Responses 替代 Images API

当前 gpt-image-2 文档按 ImageHub 的实际请求方式整理：出图请使用 /v1/images/generations 或 /v1/images/edits。不要把 /v1/chat/completions 当成图片生成入口；size、quality、output_format 等参数不会按 Images API 的方式生效。
